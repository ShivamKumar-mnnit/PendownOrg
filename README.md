# PenDown

A frontend-only React site for 1:1 mock interviews & mentorship for college
students, starting with NIT Allahabad. No backend — WhatsApp confirmations
are done via `wa.me` deep links that a human (student, college coordinator,
or admin) sends manually.

## Stack

Vite + React 19 + React Router 7 + Tailwind CSS 4 + SheetJS (`xlsx`, loaded
from `cdn.sheetjs.com` since the npm registry build has unpatched CVEs) +
`lucide-react` icons.

## Running locally

```
npm install
npm run dev      # dev server
npm run build    # production build to dist/
npm run preview  # preview the production build
```

## Pages

- `/` — Homepage (hero, offerings, why PenDown, domains, how it works, for
  colleges, testimonials, CTA). Content is original copy modeled on
  madalgos.in's structure, not copied text.
- `/book` — Student booking form (name, phone, session type, domain, resume
  link). On submit, opens WhatsApp to the admin number
  (**+91 70179 03175**, see `src/lib/whatsapp.js`) with the details
  pre-filled — the student still taps Send.
- `/colleges` — Bulk-onboarding page for placement cells. Coordinator fills
  college/contact details and picks an Excel/CSV file (parsed client-side
  just for a row-count preview — nothing is uploaded anywhere). Submitting
  opens WhatsApp with a summary message; **the actual file has to be
  attached by hand inside WhatsApp**, since a website cannot auto-attach
  files to a wa.me chat. This is a hard platform limitation, not a bug.
- `/admin` — Where you (the admin) process what colleges send you on
  WhatsApp:
  1. Save the Excel file they sent you, then upload it here.
  2. It's parsed into an editable table (name/phone/domain/resume columns
     matched case-insensitively).
  3. Set a time slot (and optionally a mentor name) per student.
  4. Click **Send** on a row to open a pre-filled WhatsApp confirmation to
     that student — you tap Send yourself. **Send All** does this for every
     student with a slot set, opening one tab every ~0.6s (browsers may
     still block pop-ups after the first one — allow pop-ups for this site
     if that happens).
  5. **Download Sheet** exports the table (with slots/mentors/sent status)
     back to Excel for your own records.
  6. Google Meet links are **not** generated by the site — per your
     workflow, you create the Meet manually and share it with the student
     and mentor yourself, closer to the slot.

  Table state is saved to `localStorage`, so refreshing the admin page
  won't lose your work.

## Admin access

`/admin` is gated by a passcode in `src/lib/adminConfig.js`
(`ADMIN_PASSCODE`, default `pendown123`). **This is not real security** —
there's no backend to check credentials against, so it only stops casual
visitors, not anyone who reads the site's JS. Change the passcode before
you rely on it for anything, and don't put anything truly sensitive behind
it.

## Known limitations (by design, given no backend)

- No message is ever sent automatically — every WhatsApp "send" requires a
  human to press Send inside WhatsApp itself. This is intentional (avoids
  needing WhatsApp Business API credentials / a server).
- Bulk Excel files from colleges arrive on your personal WhatsApp, not
  inside the app — the admin panel is where *you* re-upload and process
  them.
- "Send All" opens multiple browser tabs; some browsers throttle pop-ups
  triggered outside a direct click, so very large batches may need a
  couple of passes with pop-ups allowed.

## Deploying

It's a static site — `npm run build` produces `dist/`, deployable as-is to
Vercel, Netlify, GitHub Pages, or any static host. No environment
variables or server config needed.

## To customize

- WhatsApp number: `src/lib/whatsapp.js` (`ADMIN_WHATSAPP`)
- Admin passcode: `src/lib/adminConfig.js`
- Domains list (used in the booking form + homepage grid):
  `src/lib/domains.js`
- Homepage copy/sections: `src/sections/*.jsx`, assembled in
  `src/pages/Home.jsx`
- Testimonials are placeholder content — swap in real quotes in
  `src/sections/Testimonials.jsx` when you have them.
